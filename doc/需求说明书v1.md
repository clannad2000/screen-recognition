# screen-recognition 视频状态识别功能详细设计  
  
## 1. 文档目的  
  
本文档用于指导 Codex 在现有 `screen-recognition` 项目上增加“本地视频状态识别”功能。  
  
本阶段目标：  
  
1. 保留现有图片识别功能。  
2. 增加本地视频文件识别模式。  
3. Web 页面可以实时播放视频。  
4. 每隔 N 秒从视频当前播放位置截取一帧。  
5. 截取的帧继续调用现有 `/api/recognize`。  
6. 对模型返回的屏幕进行跨帧跟踪。  
7. 对每块屏幕分别进行状态防抖。  
8. 连续 K 次识别为同一新状态后，才确认状态发生变化。  
9. 页面同时展示：  
  
   * 当前视频；  
   * 最新检测框；  
   * 模型单帧判断；  
   * 系统已确认状态；  
   * 候选状态；  
   * 候选确认次数；  
   * 状态变化事件。  
10. Tracker、StateMachine 不直接操作 DOM，设计为独立纯逻辑模块，为后续迁移到 Python 后端做准备。

# 5. 关键设计原则  
  
## 5.1 模型输出与业务状态分离  
  
必须区分两个概念。  
  
### observation  
  
某一帧模型的即时判断。  
  
例如：  
  
```json  
{  
  "state": "黑屏",  
  "confidence": 0.91  
}  
```  
  
它只是一次 observation。  
  
### confirmedState  
  
系统经过连续多帧确认以后认为当前屏幕真正处于的状态。  
  
例如：  
  
```text  
confirmedState = 正常  
candidateState = 黑屏  
candidateCount = 2  
```  
  
页面不能因为单次模型输出黑屏就直接把系统状态改成黑屏。

```javascript

    sourceDetectionId: "screen-1",
```  

建议定义：  
  
```javascript  
/**  
 * @typedef {Object} RecognitionObservation  
 * @property {number[]} bbox  
 * @property {string} state  
 * @property {number} confidence  
 * @property {string} sourceDetectionId  
 * @property {number} videoTimeMs
```  

注意：  
  
```text

```

不能用于跨帧身份识别。

# 10. 为什么不能使用模型返回的 screen-1 作为 Track ID  
  
后端当前每一帧都会重新生成：  
  
```text  
screen-1  
screen-2  
screen-3  
```  
  
因此：  
  
```text  
Frame A  
  
screen-1 = 左屏  
screen-2 = 右屏  
```  
  
下一帧模型可能变成：  
  
```text  
Frame B  
  
screen-1 = 右屏  
screen-2 = 左屏  
```  
  
所以 Tracker 必须自己产生：  
  
```text  
track-1  
track-2  
```  
  
稳定 ID。

# 14. 抽帧尺寸压缩  
  
不建议把 4K 视频原帧直接发送模型。  
  
例如：  
  
```text  
3840 × 2160  
```  
  
可以缩放：  
  
```text  
最大宽度 1280  
保持比例  
```  
  
例如：  
  
```javascript  
const scale = Math.min(  
    1,  
    maxFrameWidth / video.videoWidth  
);  
  
canvas.width =  
    Math.round(video.videoWidth * scale);  
  
canvas.height =  
    Math.round(video.videoHeight * scale);  
```  
  
原因：  
  
1. Base64 数据减少。  
2. 模型请求更快。  
3. 模型 token/视觉计算开销降低。  
4. 当前 bbox 是 0~1000 归一化坐标，缩放不会影响 bbox 逻辑。

# 18. IoU  
  
bbox 格式：  
  
```text  
[x1, y1, x2, y2]  
```  
  
坐标仍然使用：  
  
```text  
0 ~ 1000  
```  
  
计算：  
  
```javascript  
function calculateIoU(a, b) {  
  
    const left =  
        Math.max(a[0], b[0]);  
  
    const top =  
        Math.max(a[1], b[1]);  
  
    const right =  
        Math.min(a[2], b[2]);  
  
    const bottom =  
        Math.min(a[3], b[3]);  
  
    const intersectionWidth =  
        Math.max(0, right - left);  
  
    const intersectionHeight =  
        Math.max(0, bottom - top);  
  
    const intersection =  
        intersectionWidth *  
        intersectionHeight;  
  
    const areaA =  
        Math.max(0, a[2] - a[0]) *  
        Math.max(0, a[3] - a[1]);  
  
    const areaB =  
        Math.max(0, b[2] - b[0]) *  
        Math.max(0, b[3] - b[1]);  
  
    const union =  
        areaA + areaB - intersection;  
  
    return union > 0  
        ? intersection / union  
        : 0;  
}  
```

# 19. 第一版匹配算法  
  
暂时不需要 Hungarian Algorithm。  
  
显示屏数量通常较少。  
  
采用：  
  
```text  
Greedy IoU Matching  
```  
  
即可。  
  
流程：  
  
```text  
现有 Tracks  
      ×  
当前 Observations  
  
计算 IoU Matrix  
```  
  
例如：  
  
```text  
              observation1  observation2  
  
track-1            0.88          0.03  
  
track-2            0.02          0.91  
```  
  
选择最大 IoU：  
  
```text  
track-2 ↔ observation2  
track-1 ↔ observation1  
```  
  
条件：  
  
```text  
IoU >= trackingIouThreshold  
```  
  
建议默认：  
  
```text  
0.50  
```  
  
---  
  
# 20. Greedy Matching 伪代码  
  
```javascript  
function matchTracks(  
    tracks,  
    observations,  
    threshold  
) {  
  
    const candidates = [];  
  
    for (let ti = 0; ti < tracks.length; ti++) {  
  
        for (  
            let oi = 0;  
            oi < observations.length;  
            oi++  
        ) {  
  
            const iou = calculateIoU(  
                tracks[ti].bbox,  
                observations[oi].bbox  
            );  
  
            if (iou >= threshold) {  
  
                candidates.push({  
                    trackIndex: ti,  
                    observationIndex: oi,  
                    iou  
                });  
            }  
        }  
    }  
  
    candidates.sort(  
        (a, b) => b.iou - a.iou  
    );  
  
    const usedTracks = new Set();  
  
    const usedObservations =  
        new Set();  
  
    const matches = [];  
  
    for (const item of candidates) {  
  
        if (  
            usedTracks.has(  
                item.trackIndex  
            )  
        ) {  
            continue;  
        }  
  
        if (  
            usedObservations.has(  
                item.observationIndex  
            )  
        ) {  
            continue;  
        }  
  
        usedTracks.add(  
            item.trackIndex  
        );  
  
        usedObservations.add(  
            item.observationIndex  
        );  
  
        matches.push(item);  
    }  
  
    return matches;  
}  
```

# 22. Missing Track  
  
如果 Track 没有匹配当前帧：  
  
```javascript  
track.missingCount++;  
```  
  
但是：  
  
```text  
不要修改 confirmedState  
```  
  
不要把：  
  
```text  
没有识别到  
```  
  
理解成：  
  
```text  
黑屏  
```

# 23. LOST  
  
当：  
  
```javascript  
track.missingCount >= maxMissingFrames  
```  
  
则：  
  
```javascript  
track.status = "LOST";  
```  
  
例如：  
  
```text  
maxMissingFrames = 3  
```  
  
连续三次采样没看到屏幕以后：  
  
```text  
ACTIVE  
  ↓  
LOST  
```  
  
第一版 LOST Track 可以：  
  
```text  
保留在 tracks 中  
```  
  
但不再参与 UI 主展示。  
  
建议保留：  
  
```text  
30 次采样  
```  
  
或直到视频任务停止。  
  
第一版更简单：  
  
```text  
LOST 后继续存在，  
reset 时统一清空。  
```

# 25. StateMachine  
  
Tracker 只解决：  
  
```text  
这是不是同一块屏幕  
```  
  
StateMachine 解决：  
  
```text  
这块屏幕的状态是否真的变化  
```  
  
这两个模块必须分离。  
  
---

# 27. 初始状态确认  
  
对于新 Track：  
  
```text  
confirmedState = null  
```  
  
第一帧：  
  
```text  
正常  
```  
  
不能立即确认。  
  
仍然需要连续：  
  
```text  
K 次  
```  
  
例如：  
  
```text  
正常 1/3  
正常 2/3  
正常 3/3  
```  
  
然后：  
  
```text  
confirmedState = 正常  
```  
  
但是：  
  
```text  
null → 正常  
```  
  
是否创建 StateChangeEvent？  
  
建议：  
  
```text  
不创建  
```  
  
因为这是：  
  
```text  
INITIALIZED  
```  
  
不是：  
  
```text  
STATE_CHANGED  
```

# 28. 核心状态算法  
  
例如：  
  
```text  
confirmCount = 3  
```  
  
当前：  
  
```text  
confirmedState = 正常  
```  
  
模型输出：  
  
```text  
黑屏  
```  
  
处理：  
  
```text  
candidateState = 黑屏  
candidateCount = 1  
```  
  
下一帧：  
  
```text  
黑屏  
```  
  
变为：  
  
```text  
candidateCount = 2  
```  
  
下一帧：  
  
```text  
黑屏  
```  
  
达到：  
  
```text  
candidateCount = 3  
```  
  
状态切换：  
  
```text  
正常 → 黑屏  
```

# 29. 状态机代码逻辑  
  
建议实现：  
  
```javascript  
applyObservation(  
    track,  
    observation  
) {  
  
    track.latestState =  
        observation.state;  
  
    track.latestConfidence =  
        observation.confidence;  
  
    if (  
        observation.confidence <  
        this.minConfidence  
    ) {  
  
        return {  
            changed: false,  
            event: null  
        };  
    }  
  
    const state =  
        observation.state;  
  
    if (  
        track.confirmedState === state  
    ) {  
  
        track.candidateState = null;  
  
        track.candidateCount = 0;  
  
        return {  
            changed: false,  
            event: null  
        };  
    }  
  
    if (  
        track.candidateState === state  
    ) {  
  
        track.candidateCount++;  
  
    } else {  
  
        track.candidateState = state;  
  
        track.candidateCount = 1;  
    }  
  
    if (  
        track.candidateCount <  
        this.confirmCount  
    ) {  
  
        return {  
            changed: false,  
            event: null  
        };  
    }  
  
    const oldState =  
        track.confirmedState;  
  
    track.confirmedState = state;  
  
    track.candidateState = null;  
  
    track.candidateCount = 0;  
  
    if (oldState === null) {  
  
        return {  
            changed: false,  
            initialized: true,  
            event: null  
        };  
    }  
  
    return {  
        changed: true,  
  
        event: {  
            ...  
        }  
    };  
}  
```

# 32. Confidence  
  
如果：  
  
```javascript

```  
  
建议：  
  
```text  
更新 latestState  
更新 latestConfidence

不清空 candidateCount  
```  
  
例如：  
  

中间低置信度帧被忽略。  
  
不要因为一帧置信度较低就打断连续状态。

# 34. single-flight 请求模型  
  
必须避免请求堆积。  
  
错误方式：  
  
```javascript  
setInterval(  
    recognize,  
    3000  
);  
```  
  
假设：  
  
```text  
模型耗时 10 秒  
```  
  
会变成：  
  
```text  
0 秒：请求 A  
3 秒：请求 B  
6 秒：请求 C  
9 秒：请求 D  
```  
  
这是禁止的。

# 35. 推荐调度模型  
  
Controller 保存：  
  
```javascript  
let inferenceRunning = false;  
```  
  
只有：  
  
```text  
inferenceRunning == false  
```  
  
时允许抽帧。  
  
例如：  
  
```javascript  
async processFrame() {  
  
    if (  
        this.inferenceRunning  
    ) {  
        return;  
    }  
  
    this.inferenceRunning =  
        true;  
  
    try {  
  
        ...  
  
    } finally {  
  
        this.inferenceRunning =  
            false;  
    }  
}  
```

# 36. 不建议直接使用 setInterval  
  
更推荐：  
  
```text  
一次识别完成  
      ↓  
记录 lastSampleTime  
      ↓  
等待视频继续播放  
      ↓  
满足下一采样时间  
      ↓  
下一次识别  
```  
  
最简单实现可以使用：  
  
```javascript  
setTimeout()  
```  
  
串行递归。  
  
例如：  
  
```javascript  
async runLoop() {  
  
    if (!this.running) {  
        return;  
    }  
  
    if (!this.video.paused) {  
  
        await this.processFrame();  
    }  
  
    if (!this.running) {  
        return;  
    }  
  
    this.timer =  
        setTimeout(  
            () => this.runLoop(),  
            this.config.sampleIntervalMs  
        );  
}  
```  
  
这样自然保证：  
  
```text  
模型完成  
+  
N 秒  
```  
  
之后才请求下一帧。  
  
但是这意味着：  
  
```text  
实际周期 =  
模型耗时 + N  
```  
  
---  
  
# 37. 更推荐的采样语义  
  
业务上“每 N 秒截取一帧”更准确的含义应该基于：  
  
```text  
video.currentTime  
```  
  
而不是：  
  
```text  
wall clock  
```  
  
推荐保存：  
  
```javascript  
lastSampleVideoTimeMs  
```  
  
条件：  
  
```javascript  
currentVideoTimeMs -  
lastSampleVideoTimeMs  
>= sampleIntervalMs  
```  
  
Controller 可以用：  
  
```javascript  
requestAnimationFrame  
```  
  
轻量检查。  
  
伪代码：  
  
```javascript  
tick() {  
  
    if (!running) {  
        return;  
    }  
  
    const currentMs =  
        video.currentTime * 1000;  
  
    if (  
        !video.paused &&  
        !inferenceRunning &&  
        (  
          currentMs -  
          lastSampleVideoTimeMs  
          >= sampleIntervalMs  
        )  
    ) {  
  
        processFrame(currentMs);  
    }  
  
    requestAnimationFrame(tick);  
}  
```  
  
注意：  
  
```text  
requestAnimationFrame  
```  
  
只是检查是否到采样点。  
  
不是每帧调用模型。  
  
---  
  
# 38. 模型过慢时的行为  
  
例如：  
  
```text  
采样间隔 = 3 秒  
模型耗时 = 8 秒  
```  
  
过程：  
  
```text  
视频 3 秒  
→ 请求  
  
模型处理期间  
视频继续播放  
  
视频 11 秒  
→ 请求完成  
  
下一次立刻允许采样  
```  
  
此时最新帧应该是：  
  
```text  
11 秒  
```  
  
而不是补采：  
  
```text  
6 秒  
9 秒  
```  
  
原则：  
  
```text  
只处理最新帧  
不补历史帧  
不排队  
```  
  
这就是：  
  
```text  
Latest Frame Wins  
```

# 39. 视频播放与识别解耦  
  
模型识别期间：  
  
```text  
视频继续播放  
```  
  
不要暂停视频。  
  
页面展示：  
  
```text  
视频播放状态  
AI 检测状态  
```  
  
应为两个不同状态。  
  
例如：  
  
```text  
视频：播放中  
AI：识别中  
```

# 40. 视频暂停  
  
用户暂停视频：  
  
```text  
video.pause()  
```  
  
此后：  
  
```text  
停止产生新采样  
```  
  
已经发送出去的模型请求可以：  
  
```text  
允许完成  
```  
  
完成后可以更新最后一次结果。  
  
第一版无需 abort。

```text  
清理事件列表
```  

建议：  
  
```text

```  
  
增加单独：  
  
```text  
重置  
```  
  
按钮负责彻底清空。

# 48. processFrame()  
  
完整流程：  
  
```text  
1. 检查 running  
2. 检查 inferenceRunning  
3. 从 video 获取当前时间  
4. Canvas 截帧  
5. 调用 /api/recognize  
6. 过滤 confidence  
7. 转 RecognitionObservation  
8. tracker.update()  
9. matched/new Track 调用 StateMachine  
10. 收集 StateChangeEvent  
11. 更新 UI  
12. inferenceRunning=false  
```

# 49. processFrame 伪代码  
  
```javascript  
async processFrame() {  
  
    if (  
        !this.running ||  
        this.inferenceRunning  
    ) {  
        return;  
    }  
  
    this.inferenceRunning = true;  
  
    const videoTimeMs =  
        Math.round(  
            this.video.currentTime * 1000  
        );  
  
    this.lastSampleVideoTimeMs =  
        videoTimeMs;  
  
    try {  
  
        const frame =  
            this.frameSampler.capture();  
  
        const result =  
            await RecognitionApi.recognize(  
                frame.imageDataUrl  
            );  
  
        const observations =  
            result.detections.map(  
                detection => ({  
                    bbox:  
                        detection.bbox_2d,  
  
                    state:  
                        detection.state,  
  
                    confidence:  
                        detection.confidence,  
  
                    sourceDetectionId:  
                        detection.id,  
  
                    videoTimeMs,  
  
                    observedAt:  
                        Date.now()  
                })  
            );  
  
        const trackingResult =  
            this.tracker.update(  
                observations  
            );  
  
        for (  
            const match  
            of trackingResult.observedTracks  
        ) {  
  
            const transition =  
                this.stateMachine  
                    .applyObservation(  
                        match.track,  
                        match.observation  
                    );  
  
            if (  
                transition.event  
            ) {  
  
                this.events.push(  
                    transition.event  
                );  
            }  
        }  
  
        this.renderer.render({  
            tracks:  
                this.tracker.getTracks(),  
  
            events:  
                this.events,  
  
            detections:  
                result.detections  
        });  
  
    } catch (error) {  
  
        this.handleError(error);  
  
    } finally {  
  
        this.inferenceRunning =  
            false;  
    }  
}  
```

# 55. 注意 object-fit  
  
视频元素如果使用：  
  
```css

```  
  
可能出现 letterbox：  
  
```text  
黑边  
```  
  
bbox 不能简单：  
  
```text  
x / 1000 * elementWidth  
```  
  
否则位置会偏移。  
  
最简单方案：  
  
```text  
不要人为固定 video 宽高比例  
```  
  
使用：  
  
```css  
video {  
    width: 100%;  
    height: auto;  
}  
```  
  
使 DOM 显示比例始终和视频原始比例一致。  
  
这样 overlay canvas：  
  
```text  
width = video.clientWidth  
height = video.clientHeight  
```  
  
即可。

```javascript  
function formatVideoTime(ms) {

        Math.floor(ms / 1000);  
  
    const minutes =  
        Math.floor(  
            totalSeconds / 60  
        );
```  

* 可以设置最低置信度。  
* 可以开始检测。  
* 可以停止检测。  
* 视频本身不上传服务器。  
* 周期性抽帧正常。  
* 抽帧调用 `/api/recognize` 正常。  
  
## 并发  
  
* 同时最多一个推理请求。  
* 不积压历史帧。  
* 新请求使用当前最新视频帧。  
  
## Tracking  
  
* 单屏 Track ID 跨帧稳定。  
* 多屏返回顺序变化时 Track ID 尽可能稳定。  
* 未识别屏幕不会自动判为黑屏。  
* 连续 MISS 后 Track 可进入 LOST。  
  
## State Machine  
  
* 初始状态需要 K 次确认。  
* 新状态需要 K 次连续有效判断确认。  
* 单次误判不能修改 confirmedState。  
* 返回当前状态会清除候选状态。  
* 低置信度结果不推进状态确认。  
  
## UI  
  
* 视频上显示 Track bbox。  
* 展示 confirmedState。  
* 展示 latestState。  
* 展示 candidateState。  
* 展示 candidateCount。  
* 展示 confidence。  
* 展示状态变化历史。

# 99. Codex 实现时的核心约束总结  
  
必须：  
  
```text  
复用 /api/recognize  
  
保留图片识别功能  
  
浏览器负责视频解码  
  
浏览器 Canvas 抽帧  
  
single-flight AI 请求  
  
IoU 跨帧跟踪  
  
Track ID 自己生成  
  
模型 screen-1 不作为稳定 ID  
  
MISS != 黑屏  
  
低置信度 != 状态变化  
  
状态连续 K 次确认  
  
Tracker 与 StateMachine 解耦 UI  
  
状态事件单独建模  
  
seek 时 reset tracking  
  
stop 时 abort 请求  
  
防止旧 session 响应污染新 session  
```  
  
不要：  
  
```text  
引入 OpenCV  
  
引入 FFmpeg  
  
上传完整视频  
  
并行堆积模型请求  
  
把状态机写进 Canvas 绘制函数  
  
把 Tracker 与 DOM 绑定  
  
因为 detections=[] 就判定黑屏  
  
因为单帧异常就切换状态  
```
